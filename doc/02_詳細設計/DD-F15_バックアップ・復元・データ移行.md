## 5. チェック仕様
### 5.1 単項目チェック
- 必須、型、長さ、数値範囲、日付形式、列挙値、前後空白を検証する。
- 文字列は表示用HTMLとして解釈せず、制御文字を除外する。

### 5.2 相関チェック
- 開始値と終了値、上限と下限、選択肢と正解、親データと明細の整合を確認する。
- 同一ID、同一日付、同一問題の不正重複を拒否する。

### 5.3 業務チェック
- 削除済み、対象外、期限外、候補0件、履歴不足を判定する。
- 未対応機能は実行不可とし、将来機能であることを表示する。

## 6. 詳細処理フロー
1. 基準日時を1回取得する。
2. backup領域の必要データを読込む。
3. データ版、必須関連データ、状態を検証する。
4. 入力値を正規化する。
5. 業務ルールを適用して更新モデルを生成する。
6. 関連データを論理トランザクションまたはロールバック可能な手順で保存する。
7. キャッシュされた表示状態を更新する。
8. 完了メッセージまたは結果画面を表示する。

## 7. テーブル編集仕様
|編集ID|論理テーブル／ストア|操作|キー|設定内容|条件|失敗時|
|---|---|---|---|---|---|---|
|F15-T01|backup主ストア|SELECT|機能固有キー|表示・判定対象取得|初期表示／実行前|処理中止、エラー|
|F15-T02|backup主ストア|INSERT/UPDATE|ID|正規化済み入力、更新日時|検証成功時|ロールバック|
|F15-T03|関連状態ストア|UPDATE|関連ID|集計値、状態、版|関連更新時|整合性回復|
|F15-T04|ジャーナル／退避|INSERT/DELETE|処理ID|更新前後情報|複数ストア更新時|復旧に使用|

- ブラウザー保存で物理トランザクションが使えない領域は、更新前スナップショットまたはジャーナルで補償する。
- 削除は関連データの扱いを確認し、参照破損を発生させない。

|編集ID|ファイル|方向|編集内容|文字コード|エラー処理|
|---|---|---|---|---|---|
|F15-F01|機能固有入力ファイル|入力|ヘッダー、型、必須、重複、行単位検証|UTF-8/BOM許容|行番号付きで表示|

- 当該機能がファイルを扱わない場合、直接編集はなしとし、完全バックアップ経由のみ対象とする。

## 9. 状態・データ更新順序
- 画面状態: idle → validating → processing → success/error。
- processing中は同一イベントを受け付けない。
- 保存順序は、ジャーナル、主データ、関連状態、セッション進捗、ジャーナル削除を基本とする。
- 途中失敗時は更新前情報へ戻し、不完全保存を利用者へ成功表示しない。

## 10. 例外・メッセージ
|区分|例|処置|
|---|---|---|
|入力|必須不足、範囲外|該当項目へフォーカス|
|業務|対象なし、状態変更済み|再読込または案内|
|保存|Quota、IndexedDB/localStorage例外|入力維持、バックアップ推奨|
|通信|オフライン、AI失敗|再試行、ローカル機能継続|
|予期外|実装例外|共通エラー、ログ最小化|

## 11. セキュリティ・アクセシビリティ
- APIキー、秘密情報をログ・バックアップへ出力しない。
- 外部送信対象を利用者へ明示する。
- ラベル、aria-live、aria-current、フォーカス可視化を使用する。
- Dynamic Islandとホームインジケータ用safe-areaを確保する。

## 12. テスト観点
- 正常、境界、必須、相関、重複、対象0件、保存失敗、再読込、二重押下、オフライン。

- 旧保存形式、バックアップ復元、PWA更新後のデータ維持。

## 14. v4.1詳細追補
1. 出力対象entriesを物理キー昇順へ正規化し、`format`、`version`、`appVersion`、`exportedAt`と合わせてチェックサムを計算する。
2. version 9入力は単項目検証より前にチェックサムを照合し、不一致時はlocalStorageとIndexedDBを更新しない。
3. version 2〜8入力は従来どおり互換変換し、画面には元形式を表示する。
4. 出力前に生成バックアップを同じ入力検証へ通し、自己再読込できない場合はダウンロードしない。
5. 診断結果は`role=status`、異常は`role=alert`で通知し、復元候補読込後は確認見出しへフォーカスを移す。


## 15. v4.2詳細追補
1. 健全性検査は`study-quiz-storage-transaction-v1`が存在する場合に異常終了する。
2. 保持状態は`persisted()`、容量は`estimate()`から取得し、どちらかが失敗しても他方の結果を利用する。
3. `persist()`は「端末データの保持を強化」押下時だけ呼び出す。
4. 使用率80%以上、または`quota - usage`が5MB未満なら容量警告を表示する。
5. 保持状態はバックアップJSONへ含めず、復元時にも変更しない。


## 16. v4.3詳細追補
1. 復元候補は`parseFullBackup`、現在値は`createFullBackup`で検証してから比較する。
2. Registryの各バックアップ対象について、値一致=`unchanged`、現在なし=`added`、復元候補なし=`removed`、それ以外=`changed`とする。
3. 配列は要素数、オブジェクトは1件、数値形式は件数なしとして表示する。
4. `removed`と`changed`を破壊的変更として集計し、色に加えて「削除」「置換」の文字ラベルを表示する。
5. 復元確認はブラウザー標準ダイアログに依存せず、差分直下のチェックボックスと無効化された実行ボタンで行う。
6. 復元直前に現行データを再取得・自己検証し、`study-quiz-pre-restore-<日時>.json`としてダウンロードする。生成・検証・ダウンロード開始に失敗した場合は復元処理へ進まない。
7. localStorage schema 8、完全バックアップversion 9、IndexedDB version 2を維持する。
