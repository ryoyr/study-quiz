# 問題・解説品質向上機能 設計 — 4.7.0 quality planning

## 1. 目的

既存問題を外部AIへ自動送信せず、利用者が対象と処理単位を確認したうえで品質レビュー用プロンプトを発行する。生成結果は既存version 1 JSONとして取り込み、変更前後を確認して適用・却下・再生成する。既存の問題、品質提案、ファクトチェック、初期データ更新、D1共有変更との境界を維持する。

## 2. 現状調査

旧画面の対象選択は次の処理だった。

```typescript
questions
  .filter((item) => category === "ALL" || item.category === category)
  .slice(0, limit)
```

このため、利用者から見て次が不明確だった。

- `questions`の先頭順で10・20・50問が選ばれること。
- アーカイブ除外は呼出元の`availableQuestions`へ依存すること。
- 難易度、回答方式、出典有無、検索条件を指定できないこと。
- どの問題が対象か、50問のうち何問目を処理しているか確認できないこと。
- 未確認提案がある問題を再度対象にし、登録時に重複エラーとなる可能性があること。
- 50問を1プロンプトで処理し、問題ごとの検証密度が低下しやすいこと。

旧プロンプトはcorrection／supplementとJSON契約を示すが、良問の具体的基準、誤答選択肢、回答方式別正答、重複、難易度、一次情報、過剰修正防止、出力前セルフチェックが不足していた。

## 3. 改善後の対象選択

### 3.1 選択順序

1. アーカイブ済み問題を除外する。
2. カテゴリ、難易度、回答方式、出典有無、NFKC正規化検索をAND条件で適用する。
3. 既定では未確認品質提案がある問題IDを除外する。
4. 現行問題配列の順序を保持する。
5. 10・20・50・100問のページへ区切る。
6. 表示ページ内の問題をチェックボックスで個別調整する。
7. 選択済み問題を5・8・10・15問単位へ分割する。既定は8問。

現行問題配列は初期問題の教材順または利用者保存順であり、暗黙の並べ替えを行わない。画面へ有効問題、条件一致、重複回避、現在表示、選択済み、分割数とIDを表示する。

### 3.2 フィルター

- 複数カテゴリ
- 難易度1～5
- 回答方式: `single | multiple | text`
- 出典: 指定を問わない／あり／なし
- ID、カテゴリ、サブカテゴリ、問題文、解説、出典、タグの検索
- 未確認品質提案の除外
- 対象上限と前後ページ

### 3.3 分割

大量選択は許容するが、プロンプトは最大15問、推奨8問へ分割する。各分割の編集対象JSONは分割内問題だけとし、重複比較コンテキストには選択全体のID・カテゴリ・問題文を最大100問含める。これにより1問あたりの検証密度と全体重複の確認を両立する。

## 4. プロンプト設計

### 4.1 役割と制約

AIへ「資格試験・技術研修向けのシニア問題作成者兼ファクトチェッカー」と明示し、学習目標を変えず、変更が必要な問題だけを提案させる。問題の水増し、好みだけの言い換え、根拠のない難化、情報過多を禁止する。

### 4.2 品質基準

1. 問題文が単独で成立し、曖昧さや正答の手掛かりがない。
2. singleは唯一の最適解、multipleは正解集合、textは許容回答の過不足を確認する。
3. 誤答は学習者の典型的な誤解に基づき、正答と粒度・文法・長さを揃え、相互排他とする。
4. 解説は正答理由、各誤答の不適切理由、条件、版差、例外、必要な安全上の注意を説明する。
5. 事実・正答変更は検証可能な一次情報を必須とし、出典を捏造しない。
6. 難易度1～5を知識再生、条件判断、複合条件・例外の基準で調整する。
7. 選択全体との学習目標・正答・状況設定の重複を増やさない。
8. ID、試験枠、カテゴリ、サブカテゴリ、アーカイブ状態は変更しない。
9. `proposed`には変更フィールドだけを含め、choices変更時は0開始正答インデックスを整合させる。

### 4.3 重点モード

- 総合品質
- 事実・正答・根拠
- 誤答選択肢
- 解説品質

JSON契約は従来の`study-quiz-question-quality-proposals` version 1を維持する。

## 5. 画面とワークフロー

|画面|責務|
|---|---|
|問題・解説の品質向上|選択ロジック説明、複合条件、件数、対象チェック、ページ、分割、重点、入力JSON、プロンプト、提案JSON取込、登録前プレビュー|
|問題・解説品質提案レビュー|状態・種別・カテゴリ・検索、回答方式・正答・選択肢・解説・出典・難易度の前後比較、変更項目、競合、適用・却下・再生成、seed update出力|

提案登録時点では問題データを変更しない。`pending`だけを明示確認後に適用する。再生成では前回提案を却下し、現在問題、前回要約・理由・参考情報・案を含む新しいversion 1プロンプトをコピーする。新しい提案を取り込む時点では旧提案がrejectedのため、未確認重複を生じない。

## 6. JSON互換性

### 入力

```json
{
  "format": "study-quiz-question-quality-input",
  "version": 1,
  "exportedAt": "ISO-8601",
  "questions": []
}
```

### 提案

```json
{
  "format": "study-quiz-question-quality-proposals",
  "version": 1,
  "proposals": [
    {
      "questionId": "Q-1",
      "kind": "correction",
      "summary": "提案概要",
      "reason": "判断理由",
      "reference": "一次情報",
      "proposed": {
        "text": "修正後問題文",
        "explanation": "修正後解説"
      }
    }
  ]
}
```

既存の5MiB、10,000件、問題ID、重複、許可フィールド、共通Question検証、実質変更検証を維持する。

## 7. 提案データと適用

`QuestionQualityProposal`の永続形式は変更しない。

- `beforeQuestion`: 提案作成時の完全な問題
- `proposedQuestion`: 提案適用後の完全な問題
- `pending | applied | rejected`
- 作成・更新・レビュー・適用日時

適用直前に現在問題と`beforeQuestion`を完全比較し、不一致なら停止する。問題、問題シード版、提案状態を同一localStorageトランザクションで更新する。

## 8. 既存機能との互換性

- 一括ファクトチェックの画面・JSON契約・修正提案ストレージは変更しない。
- 品質提案version 1、storage key、完全バックアップversion 10を変更しない。
- 適用済み提案のseed update version 1を維持し、`appVersion`だけ現行4.7.0へ合わせる。
- `apply_question_seed_updates.mjs`の既存overrideマージと検証を維持する。
- D1連携は適用後の`shared` Question差分だけを扱い、`local-only`は送信しない。D1 Worker、API、offline snapshotの契約を変更しない。
- 問題ID、問題マスター、初期問題、履歴、FSRS、schema 9、IndexedDB 2は変更しない。

## 9. 検証観点

- 条件フィルター、アーカイブ除外、未確認除外、元順序、ページ範囲
- 8問推奨分割と順序維持
- 誤答、解説、根拠、難易度、重複、セルフチェックを含むプロンプト
- 再生成プロンプトとversion 1契約
- 対象件数・問題・分割・個別調整UI
- 回答方式・正答・選択肢・解説・出典・難易度のレビューUI
- 既存JSON取込、適用、却下、バックアップ、seed update
- ファクトチェック、D1問題マスター、local-only除外の回帰
